4. GATE SECURITY APP & SCANNER UX
================================================================================

The mobile scanner app runs directly on security staff smartphones/tablets (iOS & Android) via web browser or PWA mode with zero app store download required.

Workflow:
📷 Scan Attendee QR Code
       │
       ▼
Cryptographic HMAC Verification
       │
       ├── Invalid Signature ──────────────► FAKE TICKET (Cryptographic Mismatch)
       │
       ▼
Check Event Date & Ticket Valid Days
       │
       ├── Pass Date != Today ─────────────► WRONG DATE PASS (Day 1/2 Notice)
       │
       ▼
Check Today's Scan Status
       │
       ├── Already Scanned Today ──────────► DUPLICATE SCAN (Scanned at Gate X at HH:MM)
       │
       ▼
Check Blacklist Status
       │
       ├── Blacklisted == True ────────────► BLACKLISTED GUEST (Alert Security)
       │
       └── Blacklisted == False ───────────► ACCESS GRANTED (Mark Day Scanned + Sound Chime)

Key UI Features for Security Guards:
- Full-Screen Color Feedback: High-contrast flash (Green = Go, Red = Stop, Yellow = Wrong Date) designed specifically for low-light Garba venue conditions.
- Audio Feedback: High-pitch double beep for entry success, low-pitch buzzer for duplicate/invalid.
- Guest Verification Card: Displays Guest Name, Pass Category (Female / Male / Couple / VIP), and Ticket ID for fast visual spot-checks.

5. JODHPUR GROUND NETWORK & OFFLINE TECHNOLOGY
================================================================================

During peak Garba hours (8:00 PM – 10:30 PM), local mobile networks (Jio / Airtel / Vi) at event grounds in Jodhpur face severe congestion. Our offline engine insulates gate operations completely:

1. Pre-Fetch Manifest: Security devices tap "Download Manifest" prior to opening gates. All valid ticket tokens are pre-stored locally in IndexedDB browser memory.
2. Sub-50ms Offline Verification: Scanners validate HMAC-SHA256 digital signatures locally without needing external API calls.
3. Automatic Background Sync: Scanners queue check-in timestamps locally. Whenever internet pulses back up or devices connect to a local Wi-Fi router, logs sync automatically with the central database.

6. ANTI-FRAUD & SECURITY DEFENSES
================================================================================

Threat Model                      | Countermeasure / System Defense
--------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
Screenshot Sharing                | Once scanned at Gate A, ticket status updates globally across all scanners within seconds. A secondary attempt with a screenshot triggers an instant DUPLICATE SCAN ALERT.
Pass-Back (Handing ticket back)   | Instant timestamp registration. Re-scanning within 5 minutes or at another gate triggers an immediate alarm.
Fake Generated QR Codes           | All QR payloads use HMAC-SHA256 Cryptographic Signatures. Counterfeit generated QR codes fail decryption and show FAKE TICKET.

8. DATABASE SCHEMA BLUEPRINT (schema.sql)
================================================================================

-- Database Schema for Rangilo Raas 2026 Ticketing System

CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 1. USERS TABLE
CREATE TABLE IF NOT EXISTS public.users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    phone TEXT NOT NULL,
    email TEXT,
    age INTEGER,
    gender TEXT CHECK (gender IN ('Male', 'Female', 'Couple', 'Other')),
    instagram TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. TICKETS TABLE
CREATE TABLE IF NOT EXISTS public.tickets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
    ticket_type TEXT NOT NULL,
    valid_days TEXT NOT NULL DEFAULT 'both' CHECK (valid_days IN ('day_1', 'day_2', 'both')),
    qr_token TEXT NOT NULL UNIQUE,
    is_used BOOLEAN NOT NULL DEFAULT FALSE,
    used_at TIMESTAMPTZ,
    day_1_scanned BOOLEAN NOT NULL DEFAULT FALSE,
    day_1_scanned_at TIMESTAMPTZ,
    day_2_scanned BOOLEAN NOT NULL DEFAULT FALSE,
    day_2_scanned_at TIMESTAMPTZ,
    is_banned BOOLEAN NOT NULL DEFAULT FALSE,
    collected_by TEXT DEFAULT 'Online Guest Portal',
    payment_method TEXT DEFAULT 'Online UPI',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. CHECKINS TABLE
CREATE TABLE IF NOT EXISTS public.checkins (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ticket_id UUID NOT NULL REFERENCES public.tickets(id) ON DELETE CASCADE,
    scan_date TEXT NOT NULL DEFAULT 'Oct 18',
    scanner_device TEXT NOT NULL,
    gate TEXT NOT NULL,
    online_or_offline TEXT NOT NULL CHECK (online_or_offline IN ('online', 'offline')),
    timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
